# 敌方扩张 项目计划（当前版本 2.5）

目标：把艾利克尔（Erekir）上的敌人，从"地图作者摆好的静态基地"变成一个按玩家规则经营的对手。它自己开矿、铺管道、建工厂和兵营、布防并向你推进，资源只来自真正送进它核心的物资。

本文件是这个项目的总纲：规则、调研结论、架构、蓝图库、里程碑和当前进度。每完成一个里程碑更新一次。

## 1. 硬性规则

| 规则 | 实现方式 |
|---|---|
| 资源不能凭空来 | 关掉游戏给敌方的"无限资源"和"自动填满核心"，敌方核心里是真实库存，每个方块建成时由游戏照价从核心扣除 |
| 建造方式和速度与玩家相同 | 每一块都由它的建造机（每个核心一台核心机，和玩家的是同一种单位）飞到射程内建成，建造速度与玩家完全相同（游戏在艾利克尔默认给敌方 0.4 倍，模组校正为相同）。建造机一次领一整段（最多 40 块），在射程内连续施工，中间不等待：只受建造速度和射程限制，和玩家拖一条线让核心机去建一样。玩家的炮塔或作战单位在工地或建造机附近时不施工。"不靠建造机直接施工"保留为一个默认关闭的开关 |
| 库存有上限，和核心绑定 | 游戏本身的核心容量规则（超出即销毁），和玩家完全一样 |
| 不超过你当时的科技 | 每个蓝图里的每种方块、兵营产的兵种，都必须是你已经研究的 |
| 有根据地地逐步推进，不凭空乱建 | 自己那一半是固有领地；越过之后，每一步新建筑都必须在它已建成建筑的若干格以内（默认 40）。唯一的例外是某种必需资源的第一处来源 |
| 不在你的炮火下施工，但不怕你的普通建筑 | 你的炮塔射程以内不建；你的作战单位在若干格以内（默认 10）时先不建，走了再建。管道、墙、工厂只算路障：绕开，或者架桥跨过 |
| 线路被截断要自己接回 | 每轮规划先检查每座矿、每座工厂的线是否还通到核心；断了就从断口改道接回（接到旧线的剩余部分或核心）。没接通的矿不算"已有来源" |
| 多个核心分头行动、共用资源 | 每个核心轮流当"主场"，各自在自己周围选址，轮到的频率和单核心时一样；库存是同一份，线路可以汇进别的核心的线 |
| 兼容地图脚本 | 脚本关联的方块、脚本坐标周围不建；未开放的区域不动 |
| 正常游玩不显示任何敌方信息 | 调试面板默认关闭 |
| 和玩家同样的补给规则 | 艾利克尔上不能手动往炮塔和工厂里放东西，卸载器也不能从核心取货。敌方同样只能靠管道供给 |
| 不针对特定地图 | 代码里没有任何地图名或坐标；每次改动都要在模组没见过的地图上验证 |

"逐步推进"取代了 2.0 的"只在自己一半建造"：那条线现在只是固有领地的边界。

**建造范围对双方相同。** 模组放的每一块都经过游戏自己的放置检查（以敌方队伍的身份），所以游戏对玩家的限制对它一样有效：对方核心周围的禁建半径（`rules.buildRadius(team)`，双方用同一条规则）、地形、单位占位等。模组不改任何放置规则。

**关于"对方建筑约 7 格内禁止建造"**（`placeRangeCheck`）：这不是艾利克尔的规则。正常的图（战役预设图、自定义图）上它是关的；只有游戏的艾利克尔**地形生成器**在生成随机区块时会把它打开。2.2 开发中我一度误以为它是星球默认规则，是因为试玩和陌生地图测试用的正是这个生成器。现在测试图在生成后把它关回去，按正常规则进行。个别地图若自己开了这条规则，敌方和玩家一样遵守：规划时把这些地面当作不可用。

## 2. 调研结论

**来源：** 网上的蓝图和打法资料、v160.7 源码、官方 15 张艾利克尔地图里作者手工摆的敌方基地。

**机制上的事实：**

- 艾利克尔的卸载器不能从核心取货。基地是"矿→管道→工厂/炮塔→多余的进核心"的流水线。
- 沙子进核心会被销毁，硅炉必须由碎岩机直供。
- 岩壁上的矿点都很小；大型等离子钻机三道光束里通常只有一两道能打到矿。
- 电力是硬约束：一级科技只有喷口上的涡轮冷凝器，一个硅炉要吃掉将近两个喷口。随机生成的地图喷口很少。
- 管道会从侧面接收物品，钻机、工厂和路由器会把东西塞给相邻的一切。
- 艾利克尔的核心机可以直接从岩壁上采铍和石墨，速度很快（约每秒 5 个）。
- 本版本大气浓缩器需要 24 热量，电加热器每个只给 3：三级的热量链非常耗电。
- 自定义地图上敌方默认没有建造单位（那是战役里 RTS AI 顺带生成的）。

**从官方敌方基地学到的摆法**（`./test.sh` 之外另有 `xtest.Study` 可以统计和画图）：

- 炮塔成组（2–3 座）。一条补给干线从背后或侧面经过，每座炮塔旁边放一个普通路由器直接喂。从干线到炮塔的支线中位数只有 2–11 格。
- 线路基本是单一物品的纯线，用普通路由器分流，不用分拣器。两座兵工厂夹着一条"以路由器结尾的死头线"共用补给。
- 墙是线，不是铺满：单格墙围成 U 形（Onset），或一排大墙挡在朝玩家的一侧并包住两翼（Basin、Atlas），背后留空。墙和炮塔之间 0–1 格。绝大多数墙在炮塔 6 格以内。
- 墙线跨过通道时用爆破门留口（Marsh）。这一条还没做。

**收集到的蓝图：** 2463 个纯艾利克尔蓝图，见 `reference/`。只作为设计参考读取。

## 3. 架构

```
Director（态势状态机）──→ 决定目标的先后
   │
Brain（决策）──→ Planner（把一件事规划完整）──→ 建造队列 ──→ ExpansionAI（建造单位执行）
   │                  │
   │                  ├─ Fitter   蓝图在地形上放哪
   │                  ├─ Lines    管道和导管怎么铺（寻路、汇入、分流、拆墙）
   │                  ├─ Plumbing 液体谁给谁
   │                  └─ Power    电怎么接（节点链、喷口发电机）
   │
   ├─ Asset      每个设施是哪个蓝图、摆在哪、处在生命周期的哪一段
   ├─ Stock      真实库存、收入统计、预留
   ├─ Net        自己的补给网：哪里上货、哪里分走；每条线带什么
   ├─ Territory  固有领地、逐步推进的范围、行军路线
   ├─ Survey     地形资源（矿面、沙面、地面矿）
   ├─ Ground     每格"现有的和已规划的"是什么
   ├─ Options    所有可调的设置
   └─ Scripts    地图脚本占用的位置
```

原则：

- **蓝图只描述"长什么样、从哪进从哪出"**，不关心放在哪。位置、朝向、镜像、排数、管道和电线每次按地形现算。
- **一个项目整体可行才动工**，任何一步失败就整体放弃。
- **建造走游戏自己的机制**：进队伍的建造队列，由敌方核心机建造，游戏按进度从核心扣料。
- **按实际运转情况调整，不只信纸面数字**：每座工厂和兵营的实际效率被持续记录。已有的在挨饿，就不再建同类的，而是先补它缺的东西，并且把新矿的线直接汇到它那条补给线的上游。

补给的几种做法：

1. **引线**：从出口铺到核心，或汇入一条带同种物品的已有线路。线路只允许同种物品汇入，所以始终是纯线。
2. **分流**：纯线上换一格为下溢管（没解锁则用普通路由器），支线从侧面引出。下溢管先喂支线，支线满了才放行，所以被分流的用户优先。
3. **分拣支线**：只用于混合线（地图自带基地的线、旧存档）。
4. **直引**：从工厂空着的一侧再引一条线。
5. **接力**：通往炮塔的支线本身可以再被分流，下一座炮塔从上一座的线上取，前线不必每次都从后方拉线。

保证不会卡死的几条：

- 没有建造单位时模组自己补（每个核心一台核心机，和战役里的规则相同）。
- 建造单位空闲时像玩家一样手动采矿，所以物资为零也能起步。
- 某种必需资源还没有来源时，找矿不受距离和领地限制，对矿点质量和水源距离的要求也放宽。
- 喷口用完时允许共用电网（一起变慢），节点链最长 40 个。
- 一轮规划超时且一无所获时，下一轮的时限逐步放宽（最多 2 倍）。

## 4. 设置

所有行为都在 设置 → 敌方扩张 里，分五组（规则、经济、军事与防御、活动范围、节奏与性能），共 38 项。默认值是"激进"的：矿和工厂不限数量、每核心 3 座兵营、最多 60 处炮塔阵地、开局 2 分钟后开始。

## 5. 蓝图库

格式是纯文本，放在 `blueprints/*.txt`：

```
[breach-battery]
breach 0 0 0             方块 x y 朝向 [设定]
duct-router -2 0 1
?beryllium-wall-large 3 -3    前面带 ? 的可有可无：有地方才放；墙会换成当时舍得用的最好的同尺寸墙
row 0 2 6                可重复成排
out -1 2                 出口
in beryllium -2 -2 1     入口：这格上的管道朝这个方向送进来
boost water 0 2          增益液体的入口：以后有了富余的水，这格放液体路由器，贴着要喂的方块

[tank-refit]
@tank-fabricator 0 0 0   以 @ 开头：加装蓝图的"锚"，必须已经立着，不会再建
tank-refabricator 3 0 0
```

液体不写端口：一个方块要什么、从哪一侧出什么，从游戏数据里读；蓝图内相邻的方块直接互相供给，其余由模组铺导管。

**已有 33 个，全部通过测试台（280 次运行）：**

| 类别 | 蓝图 |
|---|---|
| 采矿 | 等离子钻机排、碎岩机排、冲击钻机（地面矿）、大型等离子钻机（岩壁上的钨和钍，需氢） |
| 发电 | 涡轮冷凝器 |
| 工厂 | 硅炉、氧化室（需臭氧） |
| 液体 | 喷口冷凝器、电解器 + 冷凝器、不占喷口的电解器（吃涡轮顺带出的水） |
| 兵营 | 坦克/机甲/飞船兵工厂各两种摆法；三种"兵工厂 + 重构厂"（二级兵，需钨和氢，两台机器共用一条硅线） |
| 加装 | 给已有的坦克/机甲/飞船兵工厂接重构厂，各两种进料方式（共 6 个） |
| 防御 | 裂解：钨弹双炮阵地、铍弹双炮阵地、单炮 U 形墙；扩散：双炮阵地、单炮；升华（臭氧 + 储液罐）；驱散；泰坦（钍弹 + 氢） |

**还没有的：** 化学燃烧室（需要泵和芳油）、热量链（电加热器、浓缩器、各种坩埚）、主重构厂及以上、再生投影器、核心升级、装配厂。

## 7. 验证

每一层单独验证，再合起来验证：

- `./test.sh bench`：每个蓝图放在空地图上，配好地形，用模组自己的寻路接上原料和核心，跑游戏统计产量。4 个朝向 × 2 种镜像。
- `./test.sh pieces`：两座矿共用一条线、分拣支线、下溢管分流、接力分流。
- `./test.sh knobs`：每项设置改掉之后，敌方的行为是否跟着变。
- `./test.sh mind`：不跑对局就能核对的决策逻辑。态势状态机的每一次切换、设施记录的存取、加装蓝图和增益入口的读取、"必需品"在三档科技下的推导、舍得用什么墙、兵营前方留几格。
- 陌生地图测试加 `JAVA_TOOL_OPTIONS=-Dxtest.tech=early|half` 可以把敌方限制在初期或半程科技；每张图末尾多一行，写用上增益液体的设施数、换了弹药的炮塔数、升级兵种的方块数、库存有多满、处在哪个态势。
- `./test.sh sim`：无窗口运行官方战役地图，持续检查违规。
- `./test.sh wild <分钟> <plain|poor|none> <种子…>`：**陌生地图**。用游戏自己的艾利克尔地形生成器按种子造图，敌方只有一个光核心和起始物资（300 铍 + 300 石墨 / 60 铍 / 什么都没有）。这些图没有参与过开发，用来判断算法在一般地图上的表现。
- `./test.sh reload`：存档再读回后状态不变。
- `./test.sh look <存档.msav> [分钟]`：**读一局真实的存档**。打印双方的建筑和单位、全图示意、敌方当前的想法，再无人操作地往后跑若干分钟。试玩时发现问题，就用试玩目录里的自动存档（`build/play-data/saves/`）复现。
- `./play.sh [种子|random] [plain|poor|none] [敌方核心数]`：**真人试玩**。在同样的生成地图上开一局普通游戏（迷雾关闭，敌方单位按小队进攻，和战役的进攻图一致），用来试手感；`./play.sh continue` 回到上次的存档，`./play.sh watch [种子]` 是镜头停在敌方核心上的观战演示。各自使用 `build/` 下独立的数据目录（你的设置和模组的副本），不动正式游戏。陌生地图测试加 `JAVA_TOOL_OPTIONS=-Dxtest.rts=true` 可以在同样的小队规则下跑。
- `./test.sh lab`、`xtest.Study`：手工实验和对官方基地的统计、画图。

检查的违规：建到地图外或脚本位置；越过固有领地后周围没有自己的建筑（军事建筑绝不允许）；紧贴你的建筑；库存为负或超上限；系统白送被重新打开；桥接错连。

**2.1 的最终结果（2026-10-12）：**

- 陌生地图 48 张，各 40 分钟：全部发展起来（有矿、有硅厂、有兵营或炮塔），0 次违规。其中 12 张是直到最后才第一次运行的种子，8 张是物资很少或为零的开局。平均第 3.5 分钟建硅厂，第 8.5 分钟建兵营，第 13 分钟建第一处炮塔。新建炮塔 744 座，710 座有弹药（其余是刚建好还没送到）。敌方建筑离你核心最近的中位数是 72 格，最近 50 格。
- 官方战役 12 张，各 30 分钟：0 次违规。
- 模组自己最慢的一帧：约 50 毫秒，偶发。

2.0 在同一批陌生地图上的结果是 12 张里只有 5 张能发展起来。

## 8. 已知限制

- **最强模式不等于样样更强。** 它把 29 项强弱设置按最强值读取（开局不等待、每秒规划、兵营 8 座/核心、单位上限 400% 等），关掉即恢复玩家自己的值；不动真实库存、科技上限、建造方式与速度、调试面板、攒钱时长和规划时限。电网超载比例和每段炮塔数拉满反而更弱，取调好的值。资源仍是真实的，所以它的结果是"兵力优先"：20–25 分钟时兵力通常是默认的 2–4 倍，炮塔则常常更少，前 15 分钟也不一定领先，不同地图、不同次运行差别很大。要让"放开上限"稳定地变成"更强"，得先改资源在兵营和炮塔之间的分配。

- 只在艾利克尔生效（按星球，或者按敌方核心是不是艾利克尔的核心判断）。
- 被你用很厚的建筑带彻底封死的通道，它目前只会绕路或架桥（桥最多跨 3 格），不会专门派兵去清障。
- 通往炮塔、兵营、工厂的支线被截断后不会像主干线那样改道接回，只会重建原位置（那里被你占住就接不上）。
- 二级兵来得晚，在随机生成的地图上很少出现：这些图的钨只有零星的地面矿，冲击钻机又要水，水要喷口，喷口很少。
- 三级的东西（氧化物、升华、泰坦、大型钻机）规划器都会建，但前提同上，实战里很少凑齐。
- 电力：一级只有喷口。喷口少的图上，硅炉和矿机共用电网，全都跑不满。化学燃烧室还没做。
- 工厂实际开工率大约三分之二：剩下的在等石墨、沙或电。闭环补给会去补，但新矿不一定汇得进那条线。
- 每张图每次运行的结果有出入：规划按时间片进行，受当时的帧时间影响。
- 没有战略层：出什么兵、在哪布防不看你的行动。它的兵造出来就各自走向你的核心，不集结。
- 墙只跟着炮塔，不会横跨通道筑墙，也不用门。
- 人和它对打的手感没有测过；多人联机没有测过。
- 第一版存档里的旧前哨和旧兵营不再有人送料，会逐渐停摆。

## 10. 2.5 的设计：通用决策机制

**要求（2026-10-13）：** 一套鲁棒的通用 AI，用状态机之类的机制写；不为某一档科技单独做适配。科技水平只是"现在允许用哪些方块"这一个过滤条件，初期、半程、全科技走同一段代码。

**2.4 的基线（全科技，4 张陌生图，45 分钟）：** 3 张图库存堆满（2000/2000）没处花；兵营数到上限后再不出二级兵；钨被拿去砌墙（一张图 55 块大钨墙，而电解器、重构厂一个没有）；喷口全被发电机占掉，之后要水要气时"附近没有空喷口"。

**核对过的游戏机制**（`./test.sh lab lab/boost.txt`、`xtest.Mech`）：

- 等离子钻机通氢：产量 ×2.5（134 → 336）。液体路由器不是实心方块，放在钻机正前方、激光下面，不挡激光。
- 冲击钻机通臭氧：×1.86（224 → 416）。
- 炮塔通水：裂解、扩散射速 250%，泰坦 175%，驱散 183%；只在装填时耗水。
- 原地替换：同组且不更小的方块可以直接盖上去（炮塔盖炮塔、墙盖墙、节点盖节点）。付新方块的全价，旧的不返还。
- 拆除返还 50%。
- 艾利克尔的容器不并入核心容量；库存上限只看核心。一个堡垒（2000）永远买不起城塞（4000 硅）。
- 一台涡轮冷凝器顺带出 5 水/秒：两台就够一台电解器或一台冲击钻机，不必占喷口。

### 三层

```
态势状态机（Director）   起步 → 发展 ⇄ 投资 ；任何时候 → 受压 → 回到原状态
        │  每个态势是一张"目标"的先后顺序表
目标（Goal）             接线、补缺、军队、防御、收入、核心、供电、改造、攀科技
        │  目标向设施登记簿提问，向规划器要方案
设施生命周期状态机（Asset） 规划 → 施工 → 运转 ⇄ 挨饿 / 被切断 ；运转 → 落后 → 改造中 → 运转 ；→ 放弃
```

**态势**只由量出来的事实切换，并且有最短停留时间，避免来回跳：

| 态势 | 进入条件 | 做什么 |
|---|---|---|
| 起步 | 某种必需品没有一条通到核心的来源 | 只找来源 |
| 发展 | 必需品都有来源 | 军队、防御、收入、核心轮流；改造排最后 |
| 投资 | 库存长期偏满，或连续多轮什么都排不出来 | 改造、攀科技、供电排最前，然后才是铺量 |
| 受压 | 近一分钟被拆掉的建筑多，或有线路被切断 | 先接线、补给、布防，不往前铺 |

"必需品"不是写死的铍、石墨、硅：是最便宜的兵营和炮塔的造价与补给，沿工厂的原料往回推出来的那一组。

**设施**（一座矿、一座工厂、一座兵营、一处炮塔阵地、一处液体来源）各自记着是哪个蓝图、摆在哪、朝向，状态由观察得出：没建完是"施工"，效率长期不到一半且缺料是"挨饿"，线不通是"被切断"，有适用的改造是"落后"。每个状态对应一个去处理它的目标。

### 改造：三种动作，全部由数据决定

1. **加装**：在已有设施旁边补上新的部分。
   - 加装蓝图：第一行以 `@` 开头，是必须已经立着的方块（锚），其余部分相对它摆放。兵工厂前接重构厂就是这样一个蓝图。
   - 增益液体：方块"可选的、只让它更快"的液体直接从游戏数据里读（钻机的氢和臭氧、炮塔的水）。蓝图里可以写 `boost 液体 x y` 指定入口：那一格放液体路由器，贴着要喂的方块；没写就把导管直接接到方块上。
2. **原地替换**：游戏允许盖上去、而且新的更好（墙换更硬的墙、核心换更大的核心）。
3. **拆了重摆**：建造机拆掉旧的（返还一半），在原处按更好的蓝图重摆并接回线路。用于前两种做不到的情况。

"更好"按用途比较，数字都从游戏数据算：矿看每秒产量，兵营看最终兵种，炮塔看射速和弹药伤害，墙看每格血量。

### 配套的几条通用规则

- **稀缺物资留给要紧的事**：蓝图里可有可无的部分（墙），只有在它用的每种物资都宽裕时才摆；之后富余了再作为"改造"补上。
- **不占喷口也能出液体**：需要喷口的蓝图找不到空喷口时，换用不需要喷口的同功能蓝图（电解器吃涡轮顺带出的水）。
- **电网吃紧就补发电**：某个电网长期供不上，就给它接一台新的发电机，而不是只在建新东西时顺带考虑电。
- **数量到顶改拼质量**：兵营数或兵种数到上限后，军队这个目标不再空转，由改造把已有兵营升到更高一级。

|---|---|---|
| D1 | 设施登记簿和生命周期；通用拆除；存档 | 完成 |

### 2.5 的结果（2026-10-13）

同样的陌生地图、同样 45 分钟、默认设置，敌方不受攻击（玩家一方不还手）：

| | 2.4 基线（4 张图） | 2.5（8 张图，全科技） |
|---|---|---|
| 发展起来 / 违规 | 4/4，0 | 8/8，0 |
| 末尾有钨来源 | 2 张 | 4 张 |
| 出了二级兵 | 0 张 | 1 张（15 辆 locus） |
| 用上增益液体的设施 | 0 | 每张图 0–7 处，6 张图有 |
| 钨墙 | 一张图 55 块大钨墙，同时没有电解器 | 钨不到库存一半时用铍墙；富余后原地换成钨墙 |

半科技（4 张图）和初期科技（2 张图）各自全部发展起来、0 违规，建出来的东西都在那一档科技之内；半科技下有一张图出了二级兵。三档走的是同一段代码，测试里只换了"哪些内容算已研究"这一个函数。

**没做到的，直说：**

- **二级兵仍然少见。** 8 张图里只有 1 张。原因按出现次数：这半边图没有能放冲击钻机的钨矿（或者钨矿在你核心的禁建半径里，游戏不让建）；兵营是在留足前方空地这条规则之前建的，前面被自己的主干管道占了，重构厂放不下；想异地重建更好的兵营，拥挤的基地里又找不到地方。
- **库存堆满的情况还在。** 8 张图里 4 张末尾三种基础物资都是满的、连续上百轮无事可做。这几张图的共同点是一级的东西已经到顶（兵营数、每种兵的数量、能放炮塔的地方），而钨拿不到。测试里玩家不还手，兵不会损失，所以库存只进不出；真打起来兵要补，情况会不同，但这一点没有测过。
- **换弹药的机会很少。** 机制有了（新弹药的支线并进旧支线，旧分流口换回普通管道），但 8 张图里一次也没发生：裂解换钨弹只强 12%，不到 15% 的门槛；扩散换氧化物弹要有富余的氧化物线。它没有在真实对局里跑通过，只通过了编译和不触发时的回归。
- **拆旧建新只实现了兵营这一种，而且没有在陌生地图里触发成功过。** 触发条件是"加装放不下、且别处放得下更好的兵营"，目前卡在后半句。通用的拆除本身（建造机拆任意自己的方块、返还一半）是原来拆墙那段代码放开了限制，原来的回归覆盖它。
- **发电只会补喷口发电机**（电网长期供不上时找空喷口再建一台，或接到有富余的电网）。化学燃烧室、热解发电机都没做：前者要芳油，16 张陌生图里只有 7 张有芳油，而且常在对面。
- **三级及以上没有新增内容**：主重构厂要氮，氮要热量链。
- 核心升级没做：艾利克尔上容器不并入核心，一个堡垒的容量（2000）买不起城塞（4000 硅），要先有两个核心。
- 每张图每次运行差别仍然很大（同一张图这次有钨、下次没有）。上面的张数是单次运行的结果，不是稳定的比例。

## 11. 战役测试：让它当玩家把主线打一遍

**要求（2026-10-13）：** "最好的测试是让你设计的 AI 去真实地打一遍关卡，即艾利克尔的主线。难度先设定为困难，看看最远能推到哪里。""关于科技树，完全遵照主线的科技树解锁顺序，不能提前解锁。"

`./test.sh campaign <每关最多几分钟> [难度] [从哪一关开始]`（`xtest.Campaign`，无窗口，90 分钟一关约 15–60 秒）。模组里 `Brain.side` 把它切到玩家一方；敌人是游戏自己的战役敌人，不是本模组。

**和真实战役一样的：** 地图文件、关卡目标和世界处理器脚本、星球规则和战争迷雾、难度倍率（困难：敌方血量 ×1.25、出兵 ×1.5、计时 ×0.8，调用的是游戏自己的 `CampaignRules`）、每关的起始物资、敌方的小队 AI。科技用游戏自己的科技树判定：父节点已研究、要求的关卡已登陆或已攻占、要求的物品已获得，研究费从核心真实库存里分期付清。建造只用核心机，只建研究过的东西（每次开工都核对，至今 0 次违规）。

**和真实战役不一样的，都偏保守或已注明：**

- 已攻占关卡的后续产出不算，只算攻占那一刻核心里剩下的物资（可用于研究）。
- 登陆新关不收费。
- 规划时它知道整张图的矿和敌方炮塔位置（存图里读的），但只能在已探明的地面上建，没探明的要先派一个作战单位去看。第一次玩的人不知道地图，这一点它占了便宜。
- 每关限时 90 分钟。

**为了能当玩家，这次加的通用能力：**

| 能力 | 说明 |
|---|---|
| 跟着关卡目标走 | 地图要求建几个某方块、核心里要有多少某物品，自己发展没带出来的，过一分钟专门去做；要求的炮塔按正常阵地建（带弹药线），要求的核心直接去占 |
| 指挥官 | 部队在家攒够一批再一起出击，打完一个目标打下一个；新造的兵不零散跟上去，等下一批；损失过半撤回，下一批更大；敌人打到家门口时全部回防。目标先取地图要求摧毁的，只打已开放区域内的 |
| 侦察 | 想建的地方没探明时派一个作战单位去看（核心机在游戏的迷雾里不开视野） |
| 给没来源的地面矿留地 | 自己的建筑不再盖在还没开采的地面矿上 |
| 规划时间公平 | 一个目标把一轮的时间用完时，下一轮从后面的目标开始，不再饿死其他目标 |
| 先有一座炮塔 | 有了第一座兵营后，每个核心先有一处炮塔，再轮流发展 |

**结果（困难，每关限 90 分钟）。** 下面几批是开发过程中不同版本的代码，不是同一版本的重复，所以只能看大致水平：

| 批次 | 第 1 关 Onset | 第 2 关 Aegis | 第 3 关 Lake |
|---|---|---|---|
| A（3 次） | 3 胜（53–65 分钟） | 2 胜（26–33 分钟），1 次 90 分钟未完成 | 2 负（第 12、19 分钟核心被毁） |
| B（5 次） | 3 胜 2 负 | 3 次都未完成 | 没到 |
| C（5 次） | 2 胜 3 负 | 2 次都未完成 | 没到 |
| D（5 次，当前代码） | 2 胜 2 负 1 次未完成 | 2 次都未完成 | 没到 |
| 合计 | 10/18 | 2/10 | 0/2 |

普通难度跑了 2 次（B 版代码）：第 1 关 2 胜（38、51 分钟），第 2 关 2 次都未完成。

**最远到第 3 关（共 17 关），18 次里到过 2 次；多数时候止步第 1 或第 2 关。** 之后读了真人存档又改了一轮，新的结果见第 12 节。

**卡在哪：**

- **第 1 关**大约一半会输。地图开放后敌方主力压上来，它的兵和炮塔换不过（典型一局造 100–200 辆坦克、损失八成）。它的防御太薄：一关下来只有几座炮塔，铍一直紧张，同时硅堆到上限用不掉。
- **第 2 关**要先拿到 100 钨才开图。研究冲击钻机要上千物资，上一关剩得少时要等很久，等研究好，自己的基地已经长得很密，钨矿到核心的管道铺不过去（"no way to lay a line"）。拿到钨的那两次都赢了。
- **第 3 关**敌方飞行单位从第 0 分钟就来袭，开局自带的基地被拆，它连第一座矿都立不住，一直停在"起步"态势里。

**还没做的：** 守波次的关卡（第 10、13、16 关，没有敌方核心）它不会玩，目前会直接空转；研究的先后只按"关卡要求的优先、其余从便宜的开始"，没有更聪明的取舍。

## 12. 从真人存档里学到的（2026-10-13）

**要求：** "读一下我目前的这几个存档，看看人类设计的基地有什么不一样的地方和优势，尽可能学习一下。""作为玩家评测的时候，开公平竞争下的最高模式。""不要设计过拟合策略，我要策略具有泛化能力。""守波次没什么不同，就是自己发展。"

存档只读：复制到 `build/user-saves/` 后用 `xtest.Human` 统计（建筑分类计数、炮塔的弹药和冷却、成组情况、离核心多远、电力、画图）。六个存档：Onset、Aegis、Lake、Intersect、Atlas、Basin（进行中）。

**真人基地的共同点：**

| | 真人 | 改之前的 AI |
|---|---|---|
| 炮塔通水 | 71 座里 58 座有水（Onset 没解锁导管，除外） | 几乎没有 |
| 兵营 | 每关 1–2 座 | 5–8 座 |
| 第 1 关 | 约 20 分钟，造 14 辆坦克 | 34–67 分钟，造 100–200 辆、损失八成 |
| 管道 | 少数几条长主干，Aegis 全图 569 段 | 每座矿、每个用户各一条线，同一关 1500–2000 段 |
| 核心周围 | 留空，只有进核心的线 | 炮塔、兵营、节点贴着核心建 |
| 电力 | 用电量约等于发电量 | 用电量是发电量的 3 倍，全体慢速运转 |
| 进攻 | 后期把炮塔一路推到敌人门口（Basin 炮塔离核心中位数 126 格），配 13 个雷达开视野 | 炮塔只沿自己一侧布置 |
| 墙 | 每座炮塔 5–12 块小铍墙，贴着炮塔 | 相近 |

**据此改的（都是按机制写的通用规则，没有地图名和坐标）：**

- 炮塔建好就接水，只要够得着有富余的水（涡轮顺带出的就够）。炮塔的冷却水不再占用水源的份额：它只在装填时喝水，不该让钻机、电解器缺水。
- 指挥官直取敌方核心（最后一个核心倒了就赢，不必清完整个基地），第一批攒到接近上限再出发。
- 只造能到达敌方核心的兵种（按游戏自己的寻路规则判断：坦克过不了深水和墙，气垫船能过水，多足能过墙）；到不了的留守。
- 核心四周 3 格内不放实心方块，留给进核心的管道。
- 新线可以并进任何一条已有线路"最后一个分流口之后"的那一段：那一段只通向核心，混着走没有坏处。
- 还没有来源的地面矿不让自己的建筑盖住；钻机选址失败不再把整片矿区封掉。

## 13. 第二轮：测试提速、开局防守、管线改造（2026-10-13 晚）

### 测试怎么跑得快

- 单局无窗口模拟约 **400 倍速**（Lake 90 游戏分钟 ≈ 13 秒），其中游戏自身占 65–75%（建筑逐帧更新，单线程），模组占 25–35%。

- 实测：4 局并行最划算。10 局并行的总吞吐反而更低——这台机器是 4 大核 + 6 小核、无风扇，持续满载会降频。
- **并行会改变结果，不只是速度**：模组每轮规划有墙上时钟上限（默认 25 毫秒）。机器忙时每轮算得少，表现变差（同一份代码，5 局并行 + 机器发热时 Aegis 的钨矿钻机有 4/5 局放不下来，换成 100 毫秒上限后 8/8 都放下了）。测试脚手架因此把上限设为 100 毫秒。看批量结果时要记得这一点。
- 日志里每个"Laid out"现在带目标、姿态和游戏内时间，便于对开局顺序。

### 这一轮加的通用规则

防守（都是关于机制的规则，没有地图名和坐标）：

- **被打时立刻反应，不等手头的活干完。** 以前"还有东西没建完就不做新决定"，资源不够时会一直卡着，掉了 50 座建筑也不建炮塔。现在只要最近有损失、或在核心 50 格内看见对方的战斗单位，就插队做三件事：给空炮塔接弹药、给炮塔接水、再建炮塔。这些蓝图的方块排在建造队列最前面，其余方块不得动用炮塔还差的那部分库存。
- **被毁的东西不在原地白送。** 没有自己的有弹炮塔罩着的位置，被毁后先不重建。
- **炮塔从里往外补**：先补没被罩住的核心，再补最近挨打且没被罩住的位置，离核心近的优先。到敌方没有陆路（隔水）时，第一座炮塔放在核心旁。
- **地图自带的炮塔、兵工厂也算自己的资产**，照样接水、加墙、补给。Lake 开局自带的 3 座炮塔在第 8–14 秒就开始接水（通水后射速 250%）。
- **第一座炮塔排在第一座兵营前面。**
- **炮塔不再见缝就建**：一段路已有炮塔后再加、以及给矿场工厂配炮塔，只在挨打时做。（放置成功率提高后，Aegis 上曾在零敌袭的情况下建了 58 座炮塔，把研究和军队都拖慢了。）

经济：

- **认得地图自带的产能。** 开局先看 3 秒；自带的炉子、钻机只要有线通到核心，就算有这种资源的来源，不再第 0 秒重复建一整套（Lake 上以前第一分钟就铺 20+44+85 格去重复造已有的东西）。第一分钟不扩产，之后按"库存 + 近一分钟收入"判断缺什么。
- **喷口只留给发电。** 喷口格子不许铺管道和别的建筑。Lake 核心 25 格外唯一空着的喷口以前被自己的管道横穿，基地因此长期只有 360/秒的电。
- **第一处来源优先建**：某种资源还没有来源时，它的矿先于队列里其他东西建，别的方块不许动它要用的库存。
- 没通电的孤立用电建筑（比如为地图任务裸放的兵工厂）会被接上电网。

管线与选址：

- **桥的冲突规则改为精确规则。** 实测确认：桥只沿自己的朝向连到前方第一座桥。旧规则是"四个方向 4 格内有任何桥就不许放"，基地里有三四十座桥时大片地方无法跨线。现在只禁两种真会出错的情况：终点桥前方有桥；后方有桥正对着它且中间无遮挡。
- **贴线取料（dock）。** 用料建筑如果紧贴一条带着它所需物品的线，就把旁边那格管道换成下溢管：先喂它，剩下的继续走。零长度支线，不用在管道丛里找路；混合线也能用（建筑只收自己要的）。选址时先试所有"贴线"位置，再试原来的"附近找空地、拉支线"。
- **支线起点按可达距离排序。** 从终点做一次洪泛（可跨桥能跨的障碍），只尝试真能走到的分流点，由近到远；以前是直线距离最近的 8 个，常常全被别的线围死。
- **按空地选址。** 每轮量一次基地周围每格"离最近障碍多远"，把候选点挪到最近的够大的空地上；以前只在管线旁边找，而成熟基地里管线旁边恰恰最挤。

## 14. 按你的打法改决策顺序（2026-10-13 夜）

## 17. 改成按局势打分（2026-10-14 凌晨，按你的思路）

你的思路：每一刻的选择有：自己采矿、向外扩张采集、向外扩张炮塔、新建兵厂、内部整理升级、巩固内部防线；部队并行操控，不占核心机。怎么选取决于：我方兵力、敌方压力、资源、对峙局势、内部问题。并且要灵活，不要固定。

**现在的做法**：`Director.Choice` 五类选择，每轮由 `weigh()` 按局势指标打分，按分数从高到低尝试（修线、补给、必需资源、地图任务始终在最前；核心机采矿和部队指挥不占这些选择）。

| 选择 | 包含 | 分数怎么来 |
|---|---|---|
| 扩采集 | 钻机、发电机、钻机提速、新核心 | 矿没铺满时高，资源越少越高，压力越大越低 |
| 兵厂 | 第一座兵营、兵营及升级 | 兵越少、资源越多越高；矿铺满前打折扣；压力大时降低 |
| 巩固防线 | 覆盖炮塔、通水 | 随压力陡增；核心没被罩住、或矿已铺满而自建炮塔不到每核心 3 座时加分 |
| 前线炮塔 | 炮塔 | 只在两军相持时有分 |
| 内部升级 | 电力、整理管线、升级、通水 | 资源富余或内部有问题时有分；压力大时为零 |

压力 = 最近损失 ÷ 5，被看到敌军时至少 0.6；兵力 = 战斗单位数 ÷ 单位上限；内部问题 = 断线、缺料、可升级的资产所占比例。"固定先建一座炮塔"已撤掉。

**结果还不好，权重没调准**（各 12 局）：Aegis 7 胜 2 败 3 超时；Lake 0 胜 4 败 8 超时。上一版固定顺序是 Aegis 11–12 胜、Lake 1–3 败。权重是凭判断定的，每批 12 局的结果又能差 3–4 局，靠一次次手调收敛不了。下一步要用更大的批次（每组权重 24 局以上）系统地比较。

## 18. 暂停开发：机制性问题复盘与自顶向下的新架构（2026-10-14）

你的要求："先暂停所有开发。分析一下开发以来遇到的所有机制性问题。我认为我们的策略一直没有很好的自由度，导致非常不灵活，无法正确应对状况……自顶向下制定一个真正合适的，灵活的 AI 策略，把底层的各种能力改造成模块，同时又能够灵活应对各种情况。"

### 18.1 机制性问题（按根源归类）

**决策结构：一直是"排序"，不是"权衡"。** 固定目标清单 → 姿态状态机 → 按局势加权的五类选择 → 推演排序，每一版本质都是给一串目标排先后、从头试到第一个能做的。
- 一次只做一个项目，上一个没建完就不做新决定（busy 门控）：不能并行；出现过 6 分钟死锁（应急炮塔工地在火力中心建不成，整个基地停摆）。
- "做什么"与"在哪做、怎么做"分离：选择层不知道某个选择在空间上能否做好（炮塔放在火力中心、船厂放在没有石墨线的地方、矿线铺进敌军航线），做完才发现。
- 局势用全局标量描述（压力、库存比例、是否饱和、是否被攻击），丢失空间信息：一艘已被炮塔处理的快艇也让整个基地进入"被攻击"、停掉扩张和整理（第三关 62 分钟里只扩矿 1 次、整理 0 次）。
- 大量手调阈值和时间常数（耐心、驻留、重试周期、禁区时长、110 格距离上限、每核心 3 座覆盖炮塔、各种权重……），互相耦合。
- 资源预留机制层层叠加（kept、guardCost、heldBack、firsts、urgent），时而冻结一切开销，时而把炮塔的钱花在扩产上。

**物流：艾利克尔的规则让核心只是终点。** 核心不能卸货（管道卸货器 allowCoreUnload=false）、单位只能往核心放东西（onlyDepositCore）、不许混线 → 每个用料建筑都必须直接接产线。
- 核心满了还在往里送（溢出被烧），船厂却饿着（第三关核心 2000 石墨、5 座船厂一艘不出）。
- 用料建筑选址不管能否供料（"缺一种料先建，以后再接"，结果永远接不上）。
- 每条线单独寻路，基地越大越挤，寻路失败；同关 1500–2000 段管道，你的存档 569 段。
- 线路"余量"按规划推算，不是实测。电力是硬预算（喷口有限），新用电建筑仍挂在超载电网上，全体降速。

**采集：被迷雾、距离上限、粗糙距离估计挡住。** 没看过的地面不能建，核心机不开视野，坦克过不了水去看；岛屿距离按"直线×2+20"算，加上固定上限，岛上矿区永远够不着；地矿每次挑单点、切碎矿面；新采集点不评估暴露风险，矿线铺进敌军航线被反复拆，铍耗在重建上，研究卡死在飞船厂前。

**防守：艾利克尔的炮塔吃物品当弹药。** 破城炮全速每秒 1.5 铍，供弹线 0.3–0.5，打空后长时间 0–2 发；"有弹即罩住"的判定过于乐观；应急炮塔放在火力中心建不成，退到射程外又罩不住资产（开局失败从 13/48 变 36/48）；兵种克制（装甲对单发伤害）很晚才建模；炮塔数量曾在无敌袭时建到 58 座，后来又太少。

**进攻与部队。** 任何敌人靠近就召回全部出击部队（对方逐个派兵时进攻永远发不起来）；分散包围导致子弹打在不同的墙上（子弹会撞沿途建筑），哪面墙都打不穿；先到的单独送死；目标来回跳；差最后 200 血时撤退；没有兵力需求模型（后来才用兰彻斯特平方律）；造到不了敌方的兵种占电占料。

**评测。** 规划有墙上时钟上限、寻路在独立线程，同一份代码 48 局能差 7 局；12 局一批分辨不了大多数改动，我反复在噪声里调参。只看胜/负/超时，信息少；长期只在第三关上调，第 4–7 关一次实测四关全败（Intersect 7 分钟丢家、Atlas 195 个兵几乎全损、Split 卡在"100 钨"任务、Basin 13 分钟丢家）。

1. 能力和决策缠在一起：每个目标函数既决定要不要做，又决定在哪、怎么做，各带一套启发式和阈值，上层无法比较和组合。
2. 没有空间化的世界模型：不知道哪里有资源、哪里在挨打、哪里拥挤、哪条线有余量。
3. 串行单项目流水线 + 忙闲门控：没有并行、没有抢占、容易死锁。
4. 没有"流"的模型（物品、电、弹药、敌军火力），预测不了饿死、断弹、守不住。
5. 参数靠手调，评测噪声大，调不准。

### 18.7 第 4–7 关的机制与本轮规则（2026-10-14 晚）

**查清的游戏机制**
- 地图任务"核心存 N 个某物品"读的是 `state.stats.coreItemCount`，只在物品经方块送进核心（`handleItem`）时累加；单位搬运进核心（`handleStack`）不算。第 6 关 Split 的钨只在大片深水对岸（约 55 格，管道桥过不去，附近无核心区），核心机能飞过去手挖但不计数。这一关的前置研究正是"加固载荷传送带 + 加固容器"，第二个任务是建两座载荷质量驱动器：需要**载荷物流**能力（容器装货、载荷运输、卸货器经管道送进核心），AI 目前没有。

- 第 5 关前 20 分钟的铍花费：冷却水管和管桥 700–900、铍墙约 500、电力节点约 600、破城炮 900、矿机只有约 440（约一成）。

**本轮加入并测得有效的规则**
- 冷却水、墙、雷达这类加成投入，只在所需材料达到容量四成以上时做；预计会挨打（看到的敌军或下一波家里守不住）或正在交火时例外。第 5 关 10 负 2 超时 → 3 负 9 超时，第 7 关 8 负 4 超时 → 6 负 6 超时。

- 硅厂的碎石机数量按配方算（蓝图一排上限 5 → 8）；配比账把硅厂自带的碎石机计入沙的供给。

### 18.8 自己手打之后（2026-10-14 下午）

新工具：`test/hand.sh <关卡>` 开一局由命令行手打的游戏（模组不接管玩家一方），命令写进 `in.txt`：`b 方块 x y 朝向`、`l 方块 x1 y1 x2 y2`、`r x y`、`s 秒`、`m x y w h`（每格一个字符的地图）、`i`、`f`。建造机按玩家速度去建。

手打第四关 3 次，都输（第 7、12、22 分钟），和 AI 差不多。学到的：
- 工厂建在原料出口上：石墨矿机的线直接进硅炉，碎石机贴着硅炉直接卸沙，3 台就满速；第 8 分钟硅 1000，AI 同时只有一两百。

- Erekir 的管道路由器有朝向，背面不出货。

### 18.9 之后几轮（2026-10-14 晚）

查清的机制：
- 裂解炮每发打 2 发弹药（铍 1 颗 = 1 发，钨 1 颗 = 2 发），装填 40 帧，满速每秒 3 颗铍；自身只存 30 发（15 炮）。第四关第 9 波时炮塔 5–10 秒内打空，线路补不上，敌人就进来了。核心里堆满的铍、钨、石墨都取不出来。
- 第四关波次：1–3 波只从西北来，第 4 波起加东南，第 7 波起加西南，第 8、9 波各有 1–2 架飞行的 avert；守完 9 波后还要拆掉敌方核心才算赢。
- 南边有一个 1–3 格宽的入口（约 280,304），后几波的 merui 从这里直接进到核心旁边。
- 第三关：中间岛上有敌方前哨、几格铍矿和一个喷口，并通过陆地连到敌方主岛；14 艘快艇能拔掉前哨，但打到主岛核心时只剩一半。

本轮保留的规则（都按机制表述）：
- 再建一座工厂时，除了配比账，也看实测：核心里那种料已有四成以上、并且仍有管线持续送来，就算有富余。
- 炮塔弹药量按"每发几颗"计算（以前少算一半）；炮塔组新增"带弹药库"摆法（容器 + 卸载器，两波之间攒 160 颗）；核心里快没有的弹药，就不优先选用打这种弹药的炮塔。
- 炮塔单独守得住家时，兵厂优先放在生产它所需物品的工厂旁边（工厂直接交货，不用接线）。
- 出击时机：按兰彻斯特估算，三分之二的兵力就能拿下目标时就出发（炮塔单独守得住家时），不再一定要攒到上限；刚拿下目标且队伍没散，就直接打下一个，不再回去集结。
- 有两座兵厂、兵接近上限时，先加改造厂（以前要等兵厂满 8 座，所以从没出过 T2）。
- 恢复"先补矿"：家没挨打、矿机花费不超过近期总花费一半时，补矿排在炮塔、兵厂、工厂之前，付不起不等。

撤掉的：工厂单元、贴线硅炉（地形里放不下）；危急时让兵厂停工给炮塔让料（第五关变差）；给打干的炮塔补线（没效果）。

结果（每关 12 局）：第二关 12 胜；第四关 3 局守完 9 波但没拆掉核心；第五关 2 超时 10 负；第七关 3 超时 9 负；第三关全超时。

### 18.10 单位操控与进攻（2026-10-15 凌晨，按你的提示）

- 躲子弹：炮塔按目标当前速度预判，子弹要飞一段时间；快艇斜着在火线两侧来回折返（没到全速就掉头，一直在加速），距目标约自身射程六成。实验台（`xtest.DodgeLab`，1 座装满弹的裂解炮对 6 艘快艇）：站着打死 5 艘、炮掉三分之一血；现在死 1 艘、炮被拆（带冷却的炮：死 2 艘、炮被拆）。
- 切供弹链：快的单位即使在"全力攻击"时也先打供弹管线；管线一路往上追，优先打同时喂好几座炮、离炮最远的那段。
- 只拆真正守着目标的炮塔，其余绕开（第三关中间岛前哨每次都被重建，绕开它）。
- 拆下目标后兵力只剩不到六成、又打不下下一个目标时，先回去合兵。
- 消费方从附近流量最大的管线取料（炮塔在交火时一次抽空细线）。这一条之后第四关第一次赢了一局（军队提前拆掉了敌方核心，再守住全部 9 波）。
- 军队卡住的两个原因已修：目标在两个之间来回变，每变一次就换一个集结点重新集结，结果在自家核心旁站了一刻钟；集结完后一分钟没靠近目标，就判为路被堵、带回来（与回防打袭击者的时间分开计）。
- 兵厂缺电时不再另起一座（第七关开局会被兵厂抽干铍）；硅炉缺电而且没电可加时，可以在有电的地方另建一座。

第三关仍打不下：主岛 6 座裂解炮互相覆盖（每座被另外 3–4 座罩着），管线是路由器网，快艇最多 15 艘，冲到南岸 15 秒剩 3 艘。地图上只有两个核心区（我们的和敌方的），没法多放核心提高上限。

结果（每关 12 局）：第二关 12 胜；第三关 12 超时；第四关 5 局守住全部波次（另有一批 12 局里赢过 1 局）；第五关 7 超时 5 负；第七关 7 超时 5 负。第五、七关都是至今最好。

### 18.11 开源之后这一轮：可达性、工厂锚在矿上（2026-10-15）

- **兵种可达性一直判反了**：`reaches()` 拿控制寻路的编号（地面 0、悬浮 1、腿 2、船 3）去取流场寻路的代价表（地面 0、腿 1、船 2……悬浮 5），悬浮船被当成腿、腿被当成船。第四关从我方出发，地面和悬浮单位根本到不了敌方基地（BFS：约 1.5 万格的封闭区），只有腿和飞的能到；以前造的是快艇，全部卡死。
- **手打第四关开局**：两台等离子钻对着核心旁的石墨墙，管道直接进旁边的硅炉，两台崩解机贴最近的沙墙，3 分半时每秒 4.6 硅。AI 原来先找崩解机、炉子放在崩解机旁，再从别处的石墨线拉支线；第四关石墨只有 25 格墙，炉子离石墨 20 格、中间全是别的线，接不进去，石墨流进核心（核心不能卸货）就再也用不上。
- 于是：**要墙矿的沙炉，建在自家钻机出口**（`Planner.plantAtOre`：先一排钻，再离钻机出口最近的沙墙放崩解机，炉子放在两者之间，三条线都很短）。第四关第 5 分钟硅 152 → 607。
- 这带出了几条配套规则，每条都逐项关掉对比过（第二关各 4 局，关掉后 3–4 负）：
  - 布线时矿面（墙矿正前方、地面矿斑）每格多算代价，实心的非钻机建筑不放在矿面上（一座炮塔连墙压在家门口唯一的铍矿前，铍整局没挖）。
  - 崩解机不贴窄通道（垂直方向空地 ≤ 8 格）的墙：那是通往下一片矿的唯一路线。
  - 扩矿名单按"有进账"而不是"有自家矿源"：地图自带的钻机带来的铍以前从不扩。
  - 核心里某产物过半就不再加它的工厂；已有的工厂缺电而又没电可加时不再加（曾经 7 座炉子挂在 2 座的电上）。
  - 兵厂总是先试贴着炉子放；没有兵去探喷口时改建雷达。
- 试过撤掉的：缺料兵厂整体搬到炉子旁（新兵厂要钨，钨不够时进入"攒钱"卡住其它开支，4 局全负）。

结果（每关 4 局）：第四关 0 → 3 超时 1 负（守住了，但一个兵都没有，所以赢不了）；第三关 4 超时；第二关 3 胜 1 超时。

第四关还差的：兵厂（merui 是唯一能到敌方的地面兵）要钨，冲击钻的线时通时断；炉子四周被进出的线占满，后建的兵厂只能挂在路过的硅线上，线一改道就断料。下一步考虑建炉子时给消费方留一侧。

**之后撤回了上面这整批**（工厂锚在矿上及配套规则）：第二关各跑 8 局对比，可达性修复后的版本 7 胜 1 超时，加上这批之后 4 胜 4 超时——兵厂报缺硅、每个缺料兵厂都触发一整套新炉子（6 分钟内 5–6 套，每套 80–94 个方块），铍和电被抽干，第 15 分钟兵数只有原来的三分之一。改成"只在已有炉子缺石墨时才锚在矿上""给消费方供料时不走这条"都没救回来。教训：这条对第四关（石墨极少）有用，但必须由实测的缺料来触发，而不是默认；留待以后按这个思路重做。

同一轮还发现：第四关前期几乎是确定性的，同一版本 4 局常常在同一分钟输，所以 4 局对比实际只有一两个独立样本；改动带来的"变好/变差"很多只是扰动了建造顺序。之后的对比至少 8 局，或者换关卡交叉验证。

- 保留：可达性修复；单位能否躲子弹只看速度（腿式单位也算"悬浮"，merui 只有快艇速度的四成，被当成快艇去折返走位，17 个只回来 1 个）；没兵时建雷达去看喷口。
- **围攻站位**：原来是"背离附近其他炮塔的加权方向"，快艇再在两侧散开三分之一圈，邻炮打掉一半。现在在开火距离的圆上每 10° 取样，找离所有其他炮塔射程边界都至少 3 格的最宽一段，快艇只在这段里折返，接近时也绕到这段再上（第三关第一次围攻：14 艘剩 12 艘，两座邻炮一发没打；原来目标打光弹药时已经只剩 6 艘）。试过又撤掉的：每次围攻前在射程外等援兵补到"上次损失的两倍加二"；找不到安全弧时退到 0.75/0.9 倍射程、被罩住的炮不围——第三关摧毁数没有改善（各局经济差异太大，这个指标噪声很大）。

第三关给到 120 分钟仍打不下：每波 14 艘依次拆掉 179,227、161,227、174,206 后打光，敌方重建，下一波从头再来。

之后两条留下了（第三关各 8 局、90 分钟）：
- **拆下就地驻守**：拆掉一座后，队伍留在刚才围它的安全站位（其他炮打不到），压住敌方在原地的重建，援兵补到"上次围攻实测损失的两倍加二"再围下一座（最多等 3 分钟；放宽到 10 分钟没有更好）。摧毁数平均 55（原来 120 分钟才 36–42）。
- **受攻击补炮要算账**：原来每个被打到、又没有炮罩着的地方都补一座炮；第三关敌方快艇专挑外围钻机打，结果造了 12–15 座裂解炮，每座的石墨够造 2.5 艘快艇。现在按 8×8 格记录最近损失的建筑造价（90 秒减半），一个地方只有在"一座炮覆盖范围内最近的损失 > 这座炮的造价"时才补（核心照旧）。第三关炮塔降到 3–7 座，经济不再两极（原来一半的局铍断供、摧毁数个位数）；**第二关 8 局全胜（15–36 分钟，原来 7 胜 1 超时）**；第四关不变。
- 试过撤掉的：围攻时射程更远的站位（0.75/0.9 倍）——打不准，摧毁数降到平均 11；射程内有敌方武装单位先打单位（原版做法）——平均 37，没有更好。

第三关铍墙全图只有 22 格（家附近 4 格），石墨墙 26 格；快艇要石墨 50、硅 70。经济天生紧，兵力上限 15（只有两个核心区），每分钟只补约 1 艘，所以每次围攻都必须少死。最后三座炮（159,206、145,206、138,229）围着核心互相掩护，找不到安全站位；敌方船厂的单位也会持续磨掉我方残兵。

第五到七关（当前版本，各 4 局 60 分钟）：Atlas 全负（17–37 分钟，没拆到任何建筑）；Split 全超时，卡在第一个任务"核心进 100 钨"——开局带来的钨不算，钨矿在深水对岸，需要跨水的载荷物流；Basin 全超时，任务"摧毁两处目标"未完成。

- Atlas：第 15 分钟起核心铍一直 6–10，连一台钻（40 铍）都造不起，第 30 分钟起建造完全停住；石墨堆到 2000 用不上。铍收入 6.7/s、需求 13.9/s：敌方四个核心不停进攻，裂解炮的铍弹在上游就把线上的铍吃光，核心几乎收不到；再加 129 段铍墙。
- Basin：60 分钟建 3865、丢 3339，每分钟边建边丢约 70 个；石墨收入 0，硅停在 85，兵厂缺硅，整局 5 辆坦克。

### 18.12 第四关第一次稳定赢（2026-10-15）

三个 bug 级的发现，都是追到单兵行为才看出来的：
- **单位不转身**：FighterAI 从来没调用 `faceTarget()`。merui、cleroi、avert 的炮不能自己转，开火锥只有 5°，单位不正对目标就打不出去。实验台（平地、冷却的裂解炮、14 个对 1 座）：merui 原来零伤害全灭，修好后拆掉炮只损 1 个。快艇开火锥 360°，所以一直没暴露。（实验台原来默认四周深水，地面和腿式单位放进去三秒就淹死，`-Dlab.land` 才能测它们。）
- **守家打不到的目标**：家里所有单位都派去打离核心最近的一个敌人；第七波里那个是飞行的 avert，merui 打不了空中，十四个 merui 对着它"开火"，同一波的 merui 拆掉了核心。改成每个单位打它打得到的最近来犯者。
- **波次没完就出击**：第四关要守满九波再拆核心。军队在两波之间出击（集结和交战要几分钟，不是走路那半分钟），下一波打进空家。改成：有限波次的图上，还有波次要来、而炮塔单独守不住时，军队留在家里。

第四关 16 局：0 胜 → 9 胜 1 超时 6 负（剩下的多在第七波，第 28 分钟）。第二关仍 7–8 胜/8。试过撤掉的：按往返行军时间判断下一波来不来得及（低估了集结和交战时间）；波次兵力按出生点数加倍、看后三波（军队被留得太久，最后一波后才出击，50 分钟打不完，1 胜）。

### 18.15 第三关拿下（2026-10-15）

- **从防守最薄的一侧打**：快速单位打核心这类目标时，取样找被最少炮覆盖的一侧，只拆覆盖那一侧的炮；侧面清干净后，核心本身也按围攻的方式打。第三关现在先拆核心西边的 138,229（玩家说的"先打左边"），不再反复去拆东边三座会被重建的炮。
- **按暴露程度找路**：去围攻站位的路线，每 4×4 格的代价是 1 加上覆盖它的炮塔数×20（Dijkstra），不再是"绕得开就绕、绕不开就直线"。原来去核心西侧要穿过中间岛前哨，到达时只剩一半血。
- **按血量而不是人头决定什么时候打下一座**：单位不回血。记录上一次围攻实际消耗的总血量，下一次至少要有两倍再加两艘满血，否则在射程外等援兵（最多五分钟）。原来十二艘只剩五分之一血的快艇去打第三座炮，六秒剩四艘。
- 结果（16 局，100 分钟）：第三关 0 → 5 胜（45–93 分钟），11 超时；第二、四关不变。
- 试过撤掉的：围攻多一档 0.75 倍射程（无变化）；第五关为攒船厂而暂停吃铍的坦克厂（还是没造出快艇，输得更多）。

第三关剩下的超时：兵力常在 1–15 之间，远低于上限，是产量问题。到第 60 分钟核心里石墨和硅都满了，四座船厂里两座各缺一种料——核心不能卸货，而全基地只有家门口四格石墨墙一个来源；西边 8 格石墨墙因为基地西缘挤满建筑，跨水过来的线进不来。

- 第三关一局六十分钟建了 34 座涡轮冷凝器、40 座冷凝器，结束时只剩 4 座发电站：外面喷口上的发电站被敌方快艇反复拆、反复重建，光这一项花掉 4400 多铍、800 石墨。"同一处反复丢失就先停"的封禁只有采矿在选址时查；给喷口和兵营也补上这项检查后，第三关反而从 5/16 掉到 1/16——电不够了。发电站该建，问题在于没人守：下一步是让炮塔或待命部队优先罩住发电和关键产线，而不是不建。还试过给未开采的墙矿留进线通道（第五关、第三关都变差），撤回。

**跨关卡的共同根源**：基地越长越挤，新料线进不来，消费方接不到料，核心里的东西取不出来（第三关的船厂、第四关的兵厂、第五关的硅炉）。下一步需要对物流布局做结构性设计：主干线、给有矿的方向预留进线通道、消费方建在来料方向上，而不是继续加局部补丁。

### 18.16 下一阶段设计：物流布局与争夺区发展（2026-10-15，待实现）

第三关胜负的分界很清楚：赢的局到第六十分钟造了 59–70 艘快艇、船厂 4–6 座，超时局 35–67 艘、2–4 座；而石墨收入每局都是 1.5/s，正是家门口四格石墨墙全采满的产量，快艇的理论上限每分钟 1.3 艘。决定胜率的是新的石墨来源（西边八格，能把收入翻三倍），它进不来是因为跨水之后正对着自家塞满的基地边缘。第五关的硅、第四关的兵厂断料也是同类问题。逐条补丁（预留通道、线改接消费方、封禁反复丢失处、炉子锚在矿上）都试过，有的无效，有的伤别的关。

所以下一阶段按模块做，每个模块先在实验台或单关上验证，再跑全部关卡回归：

1. **基地分区**：核心周围留出"进线区"——从每个有矿的方向（包括跨水的岸边）到核心的一条主干走廊，走廊里只许铺线，不许放实心建筑；工厂、兵厂、炮塔建在走廊两侧，从走廊上的主干线分料（单物品主干，不混线）。区别于失败的"预留通道"：通道只留到"有矿的方向"且数量有限（每个方向一条主干，各物品共用走廊、分线），而不是每簇矿一条三格宽的路。
2. **消费方跟着来料走**：新的兵厂、工厂优先建在主干线旁；某个方向来的料够、而离核心远时，就在那个方向的走廊口建一组"前置产线"（钻 → 炉 → 兵厂，单元内部短线），产出的兵直接上前线，不必经过核心。
3. **跨水接入**：主干遇水时，在最窄处用桥跨（已有）；岸边留落脚点（走廊的一部分）。
4. **守住产线**：发电站和外围矿被反复拆时，"按得失补炮"按整段时间的损失算（不是九十秒），或者让待命部队站到那里——这一条在第五关需要和"兵线前出"一起做。
5. **升级链作为整体规划**：第五关要的"钨 → 氢（水、电解器）→ 电 → 改造厂"一次性规划成一个工程，而不是各自"缺什么补什么"。

验证：每个模块改完都跑第二、三、四、六关各 8–16 局（步数时钟），任何一关变差就不合入。

### 18.17 前置产线（18.16 的第 2 点，已实现）

钻机排找到了矿、却没有任何线能接回家时，记下这个矿点；家里已有兵厂、而某类兵厂吃这种矿时，就在矿那边一次性建一组产线：一排钻 → 硅炉（崩解机就近贴沙墙供沙）、第二排钻 → 兵厂、兵厂贴着炉子直接拿硅，从电网接电。钻机排出口接不出去（夹在岩壁和水之间）就换矿脉另一面；兵厂先试炉子四边紧贴的位置。

### 18.19 升级链逐环排查（第五关，对照模式 + 部队守在钨矿上）

在"核心无限建材、部队一直守在钨矿"的条件下，一环一环看为什么还是出不了 locus：

1. 钨钻机建起来了，但线被拆后，那个来源被"修剪"掉，钻机还立着，模组却把它忘了；矿位被它自己占着，于是"没地方放新钻机"，也不会去接线。→ **修好**：立着的地面钻机如果没有对应的来源，重新收编为"没接线的钻机"，走正常的接线流程。
2. 断线每轮只看第一条，钨线排在一堆铍线后面；且搜索预算按普通线给。→ **修好**：唯一来源的断线优先修，并按"第一个来源"给整张图的搜索预算（`needy`）；没接线的钻机接线也一样。
3. 钨线通到核心后，改造厂要加在旧兵厂前面，但旧兵厂在拥挤处，"料线接不进来"。→ **修好**：所有兵厂都放不下改造厂时，在有空地的地方建一座整套二级兵厂（兵工厂+重构厂），建好后拆旧的。

另：用自写的 BFS 量过，那次钨矿被自家的线围死（不用桥走不出去，用桥 82 步能到核心），说明问题不是"没路"，而是规划器在拥挤基地里找不到。护甲导管（侧面的非导管方块喂不进去，铍2+钨1）可以让线贴着钻机、工厂走而不混料，是缓解拥挤的一个手段，记下待做。

### 18.20 第七关（Basin）：兵从哪来、钱花在哪（2026-10-15）

新测试开关 `-Dxp.births=1`：敌方每个新单位第一次出现时，记在离它最近的敌方兵厂/改造厂名下，每 5 分钟打印。结果：前 25–40 分钟打过来的 80–130 台坦克，**全部**出自西北那座基地的两座坦克厂（159,488、165,488），就在任务要求摧毁的核心 (158,496) 旁边；其余基地的兵厂这段时间不出兵。论坛上通关的玩家也是"先打西北核心，因为兵从那边来"。

开局花钱（前 13–20 分钟）：铍 6000–8000，其中采矿机 2800–3000（70–75 台，大多是同一批被拆了又自动重建），炮塔 600–900。我方炮塔打得很好（30 分钟杀 100+ 台坦克），但核心最后是被从西侧射程边缘打掉的：炮塔全在东侧，西侧那片空地没有补给线，炮塔放不过去，加上一直"攒钱建炮塔"攒不够。

这一轮试过、都撤回的：
1. 同一时间只建一座兵厂（建造中或缺料就不建下一座）：Basin 30 分钟存活明显变长（基线多在 5–10 分钟丢，改后多在 11–28 分钟），细化成"只禁止吃同样缺的料的兵厂"后 Atlas 也不受影响；但 Lake 合计 4/16，HEAD 同期 12/24，拖低了 Lake（Lake 靠多建船厂赢）。
2. 按"一圈"判断核心有没有被炮塔罩住，没罩住的那侧补炮塔：炮塔还是放不到西侧（没有补给线、钱不够），无效。

### 18.21f 看"录像"找到的：围攻站位（保留）

新的测试开关 `-Dxp.frames=x0,y0,w,h,从秒,到秒,间隔[,目录]`：每隔几秒把一块地图画成一张图（我方单位白、对方橙、对方建造单位紫、空弹炮塔打黑叉），相当于录像。看第三关超时局：14 艘快艇 30 秒内就拔掉北面两座 breach（围攻本身很好），然后飞到对方核心正上方贴脸打，进了南面两座 breach 的射程，10 秒内全灭；对方随后把北面两座重建，周而复始。

**按实测判断线上有没有货（保留，效果最大的一条）**：录像里第五关南边一排 6 座 breach、第七关西边几座，建好后一直空弹。原因：规划器判断"这条线能供料"用的是计划产量——源头还立着就算有货，不管它实际出不出料（钻机断电、线断了、上游被拆）。改：每 3 秒看一眼每个源头线的前几格有没有东西，一分钟没见过货的源头不算供料。第三关 100 分钟 36 局胜 34 局（94%，上一版 77%）；第二、四、六关不变；第七关 30 分钟 16 局守住 10 局（基线 11–12），第五关不变。

### 18.21g 钻机激光只被实心建筑挡住（你指出的，已核实）

游戏里 `BeamDrill.updateLasers` 一直往前走到第一个 `Tile.solid()` 的格子：普通导管、导线管不是实心的，激光能越过；墙、钻机、工厂、炮塔、光束节点是实心的，会挡住。实验台上也验证了：一条运硅的导管横在钻机和铍墙之间，钻机照样采铍。我们原来把"钻机到矿墙之间"整条留空、连导管都不许过，判断能打到多少矿时也把任何计划中的建筑当成挡板。

改：激光路径单独记（`Ground.beams`），实心建筑永远不能放；判断打到多少矿时只有实心的计划建筑才挡。
- 第一次全面放开（任何线都能穿过激光路径）：第四关 8 局全负、第七关 16 局全负——不是激光的问题，而是钨钻机等原来放不下的东西忽然都放得下了，开局资源被一条 111 格的钨矿线吃掉，第一波来时没有炮塔；顺带暴露了"核心无炮塔时加权守家"这一项被预测排序整个覆盖掉的问题（记下，暂未改）。
- 收窄：激光路径默认仍不许走线，只有"第一个来源 / 唯一来源"这类必需线路可以穿过。还有一处依赖旧机制：给钻机加氢气增速的液体路由器本来就放在激光路径上（它不挡激光），要从新集合里临时让出来，否则第六关的电和料出不来、4 局全超时。修好后：第二、四、六关全胜，第三关 11/12，第七关 60 分钟守住 11/16，第五关不变。

### 18.21h 第七关的瓶颈链（用 Box 探针在存档里逐格看出来的）

- 石墨：家附近那片斜墙上其实有 3 台石墨钻机，标着"在采石墨"，效率 0——它们接在一个 14 个方块、没有任何发电机的孤立电网上。
- 电：我方只占着 3 个喷口（约 540/s）。34 台铍钻机约 306/s、崩解机约 77/s、一台硅炉 300/s、兵厂各 90/s，远远不够。离家最近的空喷口一个在 58 格外西边平原（敌人来袭的路上，一整局都在迷雾里——派去看的坦克每次都死在路上），一个在 61 格外东南（压在未开放区冻结炮塔的射程里）。
- 于是：没电 → 石墨钻机不转、硅炉不满 → 没硅 → 兵厂只出 3–9 台 → 打不下北边那个没有炮塔、旁边有石墨和钨的任务核心。

这一轮试过、撤回的：缺了三分钟以上的第一个来源不受攒钱锁定并允许挪开挡路的自家导管（第二关恢复 8/8，第七关仍无石墨）；给断电的钻机/工厂接电放到每轮最先（大多"没有电可接"）；侦察单位不被拉去打来袭者、雷达看喷口不等富余（侦察坦克仍死在路上）。

结论：第七关要的是一套整体打法——按电力分配（稀缺的电先给硅炉和石墨，而不是第 34 台铍钻机）、守住通往喷口的路、拿下北边资源点——而不是逐环补。

### 18.21i 接电从来没成功过（找到的 bug）

"给断电的建筑接电"（`Planner.wireUp`）只把那座建筑本身当作找电的起点，而找电的搜索只能从光束节点出发——于是它从来没成功过一次，原来的"整片没电先接电"也一直是空转。改：把它所在电网里已有的节点一起当起点。另外三处配套：
- 被压制时每轮只做补弹、补矿、冷却、炮塔，不做修复；唯一来源（按实测一分钟没见货）的断电钻机，现在被压制时也接（只接远离战场的）。
- 断电按实际拿到的电判断（满足度≈0），不按电网里有没有发电设备（不在喷口上的涡轮也算"发电设备"）。
- 实测"线上有没有货"必须是这条线该运的物品（石墨线前几格和铍线共用，原来看见铍就当有石墨）。

第七关：多数局兵力从一局 3 台变成 40–110 台，有的局拆了二三十座敌方建筑，60 分钟守住 13/16，但还没赢（90 分钟 8 局 4 负 4 超时）。第二、四、六关全胜，第三关 22/24。

### 18.22 下一步的整体设计（待和你确认）

这一整天的尝试说明，第五、七关缺的不是某条规则，而是三件结构性的事：
1. **布线骨架**：现在每条线各走各的最短路，基地被几十条平行长线切成栅栏，后来的线（钨、石墨、改造厂的料）找不到路。要做：从核心向外的几条"主干走廊"（只许走线），新的远处矿线沿走廊回家；同一方向的线并排成束（≤3 条，桥能一次跨过），束与束之间留空。
2. **守住产线**：远处的矿和线是袭扰的主要目标。要做：矿点按"值不值得守"分级，值得守的放炮塔并让一部分部队驻守（部队按平方律分配：守家、守矿、出击）。
3. **找兵源、打兵源**：敌方资源无限时，压力全部来自少数几座兵厂（第七关是西北两座，周围没有炮塔；第五关是东南两座）。要做：用侦察（快船沿来袭方向回溯）找到兵厂，派快速小队去拆、并驻守防止重建。

这三件都要改核心逻辑，回归风险大，建议一件一件做：先做 3（最独立、对第七关收益最大），再做 1，最后 2。

### 18.23 第五、七关这一轮（2026-10-16）

**第七关的真实胜利条件**（新探针 `xtest.Procs` 读出地图里的世界处理器，`-Dxp.kill=分钟:x,y:…` 模拟拆掉指定建筑）：摧毁北边两座任务核心 (290,501)、(158,496) 后，6 分钟倒计时结束，脚本在我方出生核心 (338,377) 处引爆核弹（半径 52 格、5000 伤害，我方出生基地全毁），随后全图开放、敌方按时间加强出兵，要拔掉全部 6 座核心才算赢。没有备用核心时，拆掉任务核心就等于输（探针里第 6 分钟判负）。敌方资源无限，被拆的核心约 5 分钟内就会重建；我方要在别处有核心，只能占被拆敌方核心的地块（core-bastion 要石墨 1000、硅 1000、铍 800）。所以第七关是三段式长局，现在连第一段都完成不了。

**第五关查到的事实**
- 对照实验 `-Dxp.feed`（每秒把我方所有兵厂补满料）：仍然一座核心都拿不下。所以不只是物流问题：一级坦克 stell 射程 19.5 格，比 breach 的 23.8 格短，也不会躲子弹；会躲的快艇和坦克混编时，不会触发围攻。
- 敌方东南核心 (407,251) 旁边是全部两座兵厂，40 分钟时仍只有 1 座 breach、没有墙；其余核心有 2–5 座 breach。
- 电是硬上限：一台硅炉耗电 300/秒，一个喷口上的涡轮只发约 180/秒；家附近 40 格内只有 4 个喷口。
- 铍的去向（30 分钟）：breach 2100、光束节点 1016、冷却水管和桥 1012、墙 762，而钻机只有约 700。
- 基地密到兵厂四面被路过的线包死，改造厂的料线怎么都铺不进来：给 6 万步搜索也找不到路，加上桥链也不行。
- 实验台确认：Erekir 的强化容器不与核心合并，导管卸载器也不能从核心卸货，"以核心为物流枢纽"不可行。

**保留的改动**（第二、四、六关不变，第三关 11–12/12）
1. 出击后坚持原定炮塔，直到它倒下或部队被打退（逐轮重估时，一分钟内在三个相距上百格的炮塔之间切换）。
2. 地面部队只拆护着目标或挡在路上的炮塔。
3. 家里同时有快慢两种兵时，只派会躲的出去，用围攻打法。对照组（兵厂补满料）里，第五关从 2 负 2 超时变成 0 负、拆掉 10–24 座建筑。
4. 兵厂缺料时，它三面（除了出兵的正面）各留一圈地，只给喂它的线用（对所有兵厂都留的话，第七关开局 8 局全负）。
5. 铺桥材料（铍）占上限的 40% 以上时，任何线都能用连续的桥。
6. 战斗估算按实际结果修正：被打退一次，谨慎系数 ×1.5；拿下目标 ×0.75。慢速部队满编时，要估算能赢才出门。第五关 8 局失守从 7 局降到 3–4 局，失守时间也推迟。
7. 估算"目标前面挡着多少血"时，不再算导管、水管、节点这类子弹会飞过去的东西。

**试过、撤回的**
- 给空喷口的 3×3 落点预留地面：第五关涡轮变多（2 负 6 超时），但第二、四、七关开局崩了（全图预留时第二关 0/8）。只给空喷口的最佳落点预留，第四关仍掉到 5/8、第七关开局 5/8。
- 允许涡轮压在自家线上（拆了再由 mend 接回）：第五关无变化，撤回。
- 按"见过的炮塔火力 + 距离"选先打哪座核心（开关 `xp.guarded` 保留）：第一波坦克改去更远的核心，沿途被别的基地打光，第五关 7 负，撤回为最近优先。
- 线从另一条直线下面穿过（把对方两侧的导管换成桥，"立交"）：第五关正常对局里一次都没触发；第六关 0/4、第三关 9/12，撤回。

**结论与下一步**：第五、七关的上限是结构性的，而不是哪条规则：
（1）基地布局：线各走各的，基地很快变成迷宫，后来的兵厂、改造厂、硅炉都喂不进去。需要成块的生产单元（破碎机→硅炉→兵厂直接相邻，只引一条石墨线）或主干道布局。
（2）电和外围的守卫：喷口在外围、被袭扰。
（3）第七关的阶段打法：先占一座被拆敌方核心的地块，再拆第二座。
三件都要动核心逻辑。

### 18.24 测试平台的寻路假象（2026-10-16，重要）

游戏的寻路在单独的线程里跑。批量测试以约 100 倍速模拟时，这个线程跟不上，敌我单位都按过时的路径走：结果偏乐观，而且很脆弱。主线程多做一点事（哪怕只是一个不改任何状态的诊断函数），寻路线程相对就快一点，结果就变了。实测第七关开局 30 分钟：
- 推送版、寻路异步：16 局守住 14 局；
- 同一版、寻路与游戏逐帧同步（真实游戏里寻路总是跟得上）：8 局只守住 1 局。

现在 `test/one-run.sh` 默认打开同步寻路（`-Dxp.syncpath=true`，旧方式用 `ASYNC_PATHS=1`）。**之前所有成绩都不可直接比较**，需要重测。这也解释了你实时看的局面为什么比测试数字差。

同一天试过、撤回的（默认关闭，留作开关）：
- "采矿和供电永远排第一、钻机买不起就攒钱"（`xp.econ`）：第三关 0/8，敌方快艇在头几分钟就来，第一座炮塔一直没钱造。
- "被毁的钻机、涡轮、线路不等炮塔预留就重建"（`xp.rebuildeco`）：第三关早期被拆的东西吃掉了第一座炮塔的铍，8 局失守 6 局。
- 第五关开局的硅厂、采砂机压在铍矿上：采砂机现在不能对着有矿的墙（保留）。

### 18.25 寻路同步之后这一轮（2026-10-16 晚）

**新测法下的基准**（寻路逐帧同步，有雾）：第二关 8/8、第四关 8/8、第六关 4/4、第三关 9–11/12、第五关守满 60 分钟 7–8/8（不赢）、第七关开局 30 分钟守住 5–15/16（波动大）、90 分钟 3/8 守住。

**保留**
- 敌方地面部队来袭那条路上、能打到核心的位置，必须在某座炮塔射程内；第一座炮塔就放到那条路上（只对地面能打过来的核心）。第七关开局从 3/8 到 15/16。整圈都要覆盖的版本试过：开局四分钟造了七座炮塔、没造兵厂，8 局全负。
- 采矿和供电排在炮塔、兵厂、工厂前面（第一座兵厂之后），钻机在花费份额不到一半时攒钱等它；只有核心挨打、敌人到了无炮塔覆盖的核心边、或损失大于收入时炮塔才先行。单独这一项不伤第三关；之前第三关全灭，是同时加的"被毁建筑不等炮塔预留就重建"造成的。
- 改造厂的硅、钨引不出来时，若核心存货在 40% 以上且有线路运进来，照样建，再按缺料兵厂处理（之后又卡在氢气管线）。
- 断电钻机接电后两分钟内不再重接（以前每轮重接一次，受攻击时同一台钻机被接了几十次）。
- 实时窗口保留游戏本身的迷雾，画面显示我方视野。关雾时同一份代码第五关 8 局输 7 局，之前给你看的窗口就是关雾的。

**撤回**
- 开局把地图自带产线也算作供给（按实际进核心的量）：第二、四关 0/8。核心里的货喂不了兵厂。
- 开局各物品同样短缺时按缺口大小排先后：第三关 2/8。
- 侦察每座敌方核心、按看到的炮塔和兵厂选目标：派去的慢坦克多死在路上，选择没变，无收益。
- 快艇围攻时慢速部队前去护卫：第五关一局只有 0–1 次围攻，触发不到。
- 被反复拆的地方暂不重建：断电钻机转而被接新电线，光束节点花费反而翻倍，8 局输 5 局。

**第七关中期为什么输**：核心失守时身边没有我方单位，也没有炮塔开火。breach 的弹药是铍，中期铍归零，炮塔空弹。铍的去向：40 分钟内只立项 40 个，但建了 1500、丢了 800，大部分铍花在重建被拆的钻机和节点上。开放区域里能挖的铍墙基本挖完了，要靠拿下北边（任务核心附近有石墨和钨）才能继续，而拿下任务核心又会触发 6 分钟后的核弹（见 18.23）。

## 9. 踩过的坑

- **不要在模组目录里启动游戏。** 游戏找自己的资源文件时先看启动目录、再看 jar 包；从本目录启动，它会把这里的 `bundles/` 当成自己的语言文件，界面上所有原版文字变成 `???fps???` 这样的占位符。`play.sh` 因此先切到空目录 `build/run` 再启动。试玩窗口交给人之前要**看截图**，只看日志发现不了这种问题。
- **地形生成器会偷偷改规则。** `ErekirPlanetGenerator` 生成地图时把 `placeRangeCheck` 打开（对方建筑约 7 格内禁建），正常地图没有这条。用它造测试图后必须关回去，否则测的是一条真实游戏里不存在的规则。

- **艾利克尔上单位只能往核心里放东西**（规则 `onlyDepositCore`，星球规则里设的）。任何"单位把物品送进工厂/炮塔"的做法对玩家都不成立，敌方也就不能用。服务器端的 `Call.transferItemTo` 不检查这条规则，测试不会报错，只能自己记着。
- **规划的时间上限是墙上时钟**，同一份代码在忙的机器上打得更差。批量测试并行数不要超过大核数，脚手架里把上限放宽。
- 替别的用途把核心库存"锁住"很容易死锁：锁住的往往正是建矿要用的那种资源。
- 游戏加载模组类早于创建方块，模组里在类加载时取 `Blocks.xxx` 得到的是空值。
- 噩梦模组的"聪明 AI"会打开游戏自带的基地 AI，它每帧把敌方核心填满。现在用一个什么都不做的替身顶掉它。
- 管道桥会连到前方第一个桥，不管对方朝向。
- 地图脚本用的处理器属于玩家队伍，分布在全图，不能算作"玩家建筑附近"。
- 用普通路由器或下溢管分流的线必须永远是纯线。有一次别的硅炉的出硅线汇进了石墨线的上游，硅混进了通往硅炉的石墨支线，硅炉不收，整条支线堵死。
- 两条线紧贴着平行走，两条都没法再分流：分流用的方块会把东西塞进旁边那条线。现在新线会和别的线留一格。
- 寻路的启发值如果只朝核心，新线会贴着本可以汇入的旧线一路跑回家。启发值里必须包含"到可汇入线路的距离"。
- 测试脚手架自己的检查曾经占了一帧里的 400 毫秒，被误当成模组的卡顿。计时要把检查扣掉。
- 判断"工厂在不在干活"不能只看一瞬间：缺料的工厂是一阵一阵干的。
- 通往持续消耗者（硅炉、兵营）的支线不能再被分流，否则多个用户只算了一份消耗。只有通往炮塔的支线有富余。
