# 调研：指派器、总体分区、增量改建（2026-10-22）

用户的要求：外接一个指派器，按当前阶段设计任务，逐步划出区域，交给配平器和布局器造蓝图，从零资源走到终极科技；要能做整体规划的优化、基于现有建筑的优化，需要时拆了重建（比如发电升级）。先调研，不开工。

## 一、先例

| 领域 | 做法 | 对我们有用的 |
|---|---|---|
| 游戏自带：`mindustry.ai.BaseBuilderAI` | 作弊：核心自动装满、自动刷核心机；在矿点或随机空地上摆预制蓝图，只避开单位路线 | 没有规划可借鉴，确认这是空白 |
| Factorio Learning Environment（NeurIPS 2025） | 大模型代理建厂 | 空间推理和长期规划都弱，6 台以上机器协调不了；说明这块要靠搜索和优化，不能指望"会玩的代理" |
| 星际争霸建造顺序（Churchill & Buro 2011 起，BOSS） | 深度优先分支定界 + 抽象，实时给出人类职业水平的建造顺序 | 开局（资源少、选择少）用精确搜索；本分支 `Timeline` 已是这一路 |
| 星际争霸建筑摆放（Richoux 等 AIIDE 2014；Barriga 等） | 约束优化 / 局部搜索做堵口；遗传算法 + 模拟攻击评估基地布局 | 布局要按对抗压力评估，不只看产能 |
| RTS 分层规划（Ontañón & Buro IJCAI 2015 的对抗式 HTN；Leece 2014） | 单一高层规划器统管宏观，比"战略层 + 战术层各自为政再通信"好 | 指派器不要另起一层，和路线图里的指挥层合成一个决策层 |
| 动态设施布局 DFLP（Rosenblatt 1986；综述 Balakrishnan & Cheng 1998、2020） | 多时段布局，代价 = 物流 + 搬迁（重排）代价；两派：自适应（允许重排）与鲁棒（一个布局通吃所有时段） | 改建就是重排代价；"总体规划要不要定死"就是自适应与鲁棒之争 |
| 芯片 ECO 增量布局（Roy & Markov 2007）与留白（whitespace） | 只修改需要修的区域，保留好的部分；各区域预留空白供以后插入，但均匀留白会拉长连线 | 增量布局 = 已有建筑固定 + 只在新区域里重算；分区时在增长点预留空地，而不是处处留 |
| 发电扩张规划（generation expansion planning） | 多年 MILP：新建、退役、替换一起决策；滚动时域（每年定下一年，下一年重算），或代表性时段降维 | 科技与产能的多阶段决策照这个建模；"燃烧发电 → 冷凝机"就是退役 + 新建 |
| 多阶段随机容量扩张（Ahmed 等 2003；2023 风险规避多阶段） | 情景树、固定费用、Benders | 对手打法、经济好坏用几个情景，不靠单一预测 |
| Satisfactory / Factorio 规划工具 | 线性规划算配比，个别用约束规划求最小空间布局 | 和我们的配平器同类，没有分阶段和增量 |

结论：游戏里没有现成的解法；运筹学里每一块都有成熟模型（建造顺序搜索、多时段扩张 MILP、动态设施布局、增量布局与留白），但没有人把它们组合进一个实时游戏 AI。难点在组合与算力，不在单个算法。

## 二、与本分支已有部分的关系

已有（`src/expansion/econ/`）：配方与地块、配平与建造顺序（`Planner`、`Timeline`）、整条流水线 `Plan.make`、按"离现有产出几步"分层的 `gate`、爬科技的 `next`、布局（`Grid`、钻头 MWIS、退火摆放、协商布线、Steiner 供电）、执行（`Hand` 核心机，按公平规则建造）。路线图 §27 已写了"升级作为候选动作（成本 = 新造价 − 拆旧返还，收益 = 增产）"和"指挥层：持续调度，在扩张、升级、防御、造兵之间分配，规划移出主线程"。

新写的 `bp/` 生成器比 mod 里的布局强（加热团、载荷与缓存、规则核对、真引擎验证），但还在 mod 之外，依赖 OR-Tools 的本地库。

## 三、建议的结构

1. **决策层（指派器 = 指挥层，一个，不分两个）**：滚动时域的多时段 MILP。时段约一两分钟，往后看几个时段，只执行第一个，状态一变就重算。
   - 决策：建、升级、拆哪些"模块"（抽象的，不带几何），研究，造兵与防御的投入。
   - 约束：物料和电的平衡（按时段），**核心机的建造时间是每个时段的产能上限**（开局最紧的就是它），各分区的面积（汇总的），科技前置。
   - 代价：用户的三项（空间、材料、建造时间）加上停产；拆除只返还一部分（规则里的返还倍率）。
   - 不确定性：经济悲观、乐观，对手的几种打法，各一个情景，取稳健的方案。
   - 开局资源少、选择少，用精确的建造顺序搜索（现有 `Timeline`，BOSS 一路）；中后期用 MILP。
2. **分区层**：在整张图上把模块当矩形做粗粒度布图规划（就是现在的退火摆放，粒度更粗），在增长点留出空地，留多少按"以后要放的模块"的期望面积，作为代价算，不写死比例。分区随决策层滚动更新；已建的分区移动要付重排代价（DFLP），所以一般不动。
3. **区域布局层**：`bp/` 的生成器，加"增量模式"：已有建筑当固定实体，已有线可以开分流口接出；只在划给它的区域里摆放、布线；拆除作为候选动作，代价同上。
4. **执行层**：`Hand`。区域内也要排建造顺序（先建的先产出），这是区域布局交给执行层的另一项输出。
5. **反馈**：每次实际布局和建造的统计（每条线的平均长度、布局额外占地、实际建造时间、模块真实产量）回填给决策层的估计值，滚动更新。

## 四、风险

1. **算力**：现在的生成器单个区域 10 秒到 10 分钟，对局里不能这么等。办法：常用模块离线生成、真引擎验证后存成模块库（带端口的刚性单元），对局里以组合和接线为主，现场全量综合只用于特殊情况；规划放后台线程，分帧推进。
2. **依赖**：OR-Tools 带本地库（几十 MB，分平台），作为 mod 发给玩家不现实，安卓更不行。对局里的求解要有纯 Java 的替代（mod 里现有的退火、协商布线、Bellman-Ford 都是纯 Java）；OR-Tools 留在离线生成模块库和测试里。
3. **总体规划定得太死**：对手、地图、科技时机都会变。总体规划要能滚动重算，增长点留空地；已建的不轻易动。
4. **组合的接口**：三层之间传什么（模块的面积估计、端口、建造时间）决定成败；面积和线路开销要用实测统计，不能拍脑袋。

## 四点五、用户的修正：模块带端口，上层只连物料（2026-10-22）

用户指出：分层规划难以利用已有模块的副产物，只看局部也有各种问题；建议把现有求解器改成输入输出端口模块，上层只负责连接物料。

采纳，具体为：

1. **模块 = 带端口的黑盒，由现有求解器（配平 + 布局）生成**：占地形状；端口（位置、朝向、物品或液体或载荷、速率范围）；三项代价；电力收支。副产物和富余产能都暴露为可选输出端口（没人接时能堵则堵，必须排走的在模块内自带排放）。上层也可以提端口要求（某侧给出某物多少），生成器按要求再出一版。
2. **上层 = 模块级的全局配平**：所有现有和候选模块的输出端口是供给、输入端口是需求，一个模型里决定连哪些端口、建或升级哪些模块；老模块的副产物在这里是零成本供给，自然被用上。连线代价按模块间距离，连线本身交给协商布线器（端口到端口）。
3. **列生成防"只看局部"**：主问题（模块级配平）给出每种资源的影子价格；子问题（模块生成器）按价格设计新模块，只有能降低总代价的才加入候选；迭代到没有更好的为止。全局的取舍通过价格传给局部。同一思路也可以写成 logic-based Benders（`algorithms.md` §5）。
4. **空间**：分区层定模块位置，连线距离反馈给主问题，交替几轮；已建模块位置固定，改建是"拆除 + 新模块"的候选，同一套代价比较。

顺序随之调整：先把求解器改造成模块生成器（端口、可选输出、端口要求）；再做模块级全局配平（带影子价格）；再做列生成的循环；增量、改建、分区都在其上。

## 五、建议的顺序

1. 先把 T5 这一关收尾（三种 T5 一次布干净、真引擎达到计划产量），并提速。
2. 增量模式：已有建筑 + 一块区域 → 新任务（小例子：在现有硅厂旁加一条碳化物线）。
3. 拆除与改建作为候选动作（小例子：燃烧发电换成冷凝机，算不算得过来）。
4. 模块库：离线生成、验证、存档，对局里组合。
5. 分区层。
6. 决策层（指挥层）：滚动 MILP，接上 `Timeline`，在线三的沙盒里从降落物资走到终极科技，对比现在卡在钍的版本。
7. 把需要的部分搬进 mod（纯 Java 求解），后台线程。
