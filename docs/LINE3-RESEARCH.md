# 线三调研：自适应蓝图生成器（2026-10-22）

目标：给定一块地图区域（地形、矿位、喷口、液体地面）和一个生产目标，算出一张只属于这块地的布局（机器、导管/桥、电力节点、液体管道、载荷传送），瞬间放下后能按计划产量运转。测试中取消建造时间，资源充足。

分阶段验收：
1. **布线**：狭窄空间里所有该连的线都连通、不违反物流规则、空间利用率高。
2. **配平与运转**：放进游戏后，每台机器实际进出速率等于计划，目标产物按计划产量出货。
3. **最终**：搭出能生产所有单位的完整工厂。

所有游戏规则和数据都来自 v160.7 源代码（`~/src/Mindustry-v160.7`，与服务器上的 jar 同版本）和游戏内容数据，不靠跑对局反推。详细报告（英文，带源代码行号）在 `docs/research/`：

## 二、物流规则（布局必须遵守的）

### 物品（`items.md`）
1. **导管（duct）**：容 1 个物品，**从后面和两侧收、只往正前方送**，约 15 个/秒。前方拒收时整条线被队头卡死；两路合流无公平机制，一路可能被饿死。
2. **装甲导管（armored-duct）**：侧面只收"指向它的导管类方块"，机器、钻头、分配器不能从侧面塞进来。
3. **机器和钻头往四周所有接收者推产物**（轮询 `dump()`）。贴着机器侧面经过的普通导管会收到产物，包括这台机器自己的进料线 → 产物被送回 → 进料线堵死。贴机器的线段要用装甲导管，或只让线的最后一格正对机器。
4. **混料进机器会永久死锁**：机器每种原料各存到容量上限；某种料多送时会填满并卡在线头，另一种料再也进不来。不混线，或者在机器前用溢流导管把多余的分走。
5. **分配器 / 溢流 / 反溢流导管只从背后收**；过滤分配器：选定物品往前，其他往两侧。
6. **导管桥**：最多跨 3 格，可越过任何建筑；连向前方遇到的第一个同类桥，**不论对方朝向**，所以别的线的桥放进跨度里会截走连接。桥是实心的，会挡住等离子钻的光束，放在兵工厂出口正前方会让单位出不来。
7. **Erekir 没有交叉器（junction）**，线交叉只能用桥。
8. **核心拿不出物品**（卸载器不能从核心卸）；核心会烧掉沙等不可建造物品，超容量也烧，所以通往核心的线永远不堵。
9. **兵工厂**四面收料，只收当前配方的物品，上限为需求的 2 倍；正前方中心格被实心建筑挡住时单位出不来，工厂永久停转。

### 电力（`power-liquids.md`）
1. **用电机器之间贴着不通电**；只有贴着发电机、电力节点（或浪涌传送带等少数导电方块）才通。每台用电机器都要被一条光束照到，或贴着节点/发电机。
2. **电力节点光束**：从节点中心沿四个方向，射程 10 格（beam-tower 23），**遇到第一个有电力的建筑就停**，每个方向只连一个；光束穿过墙、导管、管道等；Erekir 没有绝缘方块。
3. **电不足时整个电网所有机器按同一比例减速**；机器速度取电、液、热三者比例的最小值。

### 液体与热量（`power-liquids.md`）
1. **强化管道**侧面只收管道、液桥；机器、泵、液体路由器必须在它正后方。指向空地会漏液。
2. **液桥**射程 4，规则类似导管桥。
3. **电解槽只从两侧出**：臭氧出右侧（朝向+1），氢气出左侧（朝向+3）。其他机器往所有相邻接收者推液体，可能倒灌进自己的进液路由器。
4. **一根管道只装一种液体**；熔渣遇可燃液体会互相损坏。
5. **管道流量随长度下降**（推算）：任意长度约 90/s；约 47 格内 120/s，23 格内 180/s，12 格内 300/s。浪涌坩埚、氰合成器各要 160/s，必须短线。
6. **热量只从正面出**；热路由器 1/3 分给前左右三面；机器得热 = 热源输出 ÷ 热源边长 × 接触格数；多个热源相加，多余的浪费，不足时按比例减速。
7. **危险**：氧化室产物不运走会停转、热量归零；通量反应堆缺氰会爆炸；新塑反应堆罐满会爆炸。

### 载荷：单位与墙块（`payloads.md`）
1. **交接只看一格**：方块把产物交给它正前方 `size/2+1` 处那一格上的建筑。方块直接对方块交接不需对齐；载荷传送带要求严格对齐（3×3 必须在线上，5×5 中心偏差 ≤1 格）。
2. **前方拒收时不会改放到地上**：前方有任何能接收载荷的方块，它就一直等，永远不放。单位类型不对、对方满了、从改造厂的正面送入，都会让上游永久卡住。
3. **兵工厂 → 改造厂 → 高级改造厂**可以直接贴着连，不用传送带；改造厂从背后和两侧收、正面出。
4. **总装厂（assembler）**：组装区是正前方 13×13（前方 3~15 格、左右各 6 格）；区内可以有建筑，只有出生点要空。新单位不会自己离开，必须被命令走开，否则总装厂停转。两个总装厂的组装区不能重叠，也不能紧挨（至少隔 1 格）。四面收载荷，一次一个，整批到齐才开工。
5. **模块（module）**不是装在背后，而是放在组装区边界外、面朝区中心。有没有模块决定造 T4 还是 T5，切换会重置进度。
6. **尺寸限制**：载荷传送带最大只能运 3 格大小的单位，obviate 和全部 T4/T5 都运不了；obviate 改造厂面对传送带会永久卡死。
7. **构造器（constructor 3×3）**造大墙：大钨墙 5 s 一块、大铍墙 4 s、大碳化物墙 1.67 s。必须设置要造的方块，且必须对着能收墙块的东西。
8. **载荷传送带**全局同步节拍，每 45 帧移动 3 格，约 1.33 个/秒。

## 三、算法调研结论（`algorithms.md`）

把问题看成芯片设计里的"布局 + 布线"：
- 机器 = 单元（带进出料面）；
- 物料流 = 有运量要求的连线；
- 导管/桥 = 布线轨道；
- 电 = 另一层连通问题；
- "机器往邻居乱推货" = 布局规则冲突。

| 方法 | 能做到 | 结论 |
|---|---|---|
| 精确联合求解（CP/SAT/整数规划同时摆放 + 布线） | Factorio 研究（Patterson 等 2023）约 100 格就几分钟，之后不可解；量子点电路、微流控芯片、CGRA 映射同样只能做很小的规模 | 只适合小窗口 |
| **模拟退火摆放 + 协商拥塞布线（PathFinder，FPGA 工具 VPR 的做法）** | 工业上可扩展；用于 CGRA 映射（SPR） | **主方案** |
| 设施布局整数规划、解析式摆放 | 不建模走线容量 / 面向超大芯片 | 不合适 |
| 分解法（逻辑 Benders） | 主问题配平，子问题检验布局，失败时生成约束 | 用来联结配平和空间 |

纯 Java 可用的求解器：Choco（约束规划）、Sat4j（SAT）、ojAlgo（线性 / 小整数规划）。OR-Tools 要本地库，只适合离线用。

最大风险：布线模型和游戏真实规则不一致（推货进所有邻居、分配器回推、导管收料方向、桥的截连、混料卡死、光束遮挡）。以往所有游戏上的尝试都栽在这里，所以必须有独立的规则校验器和游戏内实测。

## 四、建议方案（待讨论）

```
  目标（产物 + 速率）  +  区域（地形、矿、喷口）
            │
  ① 精确配平（整数规划）
     - 每种物品/液体/电/热收支平衡，机器台数取整
     - 每条物料流需要几条导管（速率 ÷ 15/s 向上取整），液体流按长度限速
            │
  ② 选址：每种机器的合法位置（矿、喷口、可建地面）
            │
  ③ 摆放：模拟退火
     - 代价 = 连线长度 × 导管条数 + 拥挤估计 + 违规（推货邻接、热面朝向、载荷对齐）
            │
  ④ 布线：协商拥塞（PathFinder）
     - 在（格子，朝向）状态图上搜索，桥是跳跃边
     - 多条物料流反复重布，被争抢的格子越来越贵，直到没有冲突
     - 液体同层竞争；电力节点按光束可见性铺设
            │
  ⑤ 校验：规则校验器（按源代码规则静态检查：方向、推货泄漏、混料、遮挡）
     + 游戏内实测（真实引擎，小地图，瞬间放置，测每台机器实际速率）
            │
  ⑥ 失败反馈：先重新摆放；不行就给①加约束再求
     - 空间约束：占地 + 走线格 ≤ 可用格
     - 瓶颈约束：某个通道最多容纳几条线
     - 冲突组合禁止
```

另外：当某一块区域反复布不通时（约 100 格以内），用 SAT/约束规划精确求解那一小块，要么修好，要么证明不可行，变成一条可靠的约束。

### 测试计划
1. **小地图生成器**：在真实游戏引擎里造 N×M 的小地图，可指定墙、矿墙、地面矿、喷口、液体地面的位置。资源无限、建造瞬间完成。
2. **阶段一（布线）**：先在极小地图上测"两三台机器 + 几条线"，逐步加紧空间。指标：全部连通率、空间利用率、违规数（校验器）。
3. **阶段二（配平 + 运转）**：硅、氧化物、碳化物等单条产线。指标：实测产量 / 计划产量、机器运转占比。
4. **阶段三**：逐级到全兵种。
